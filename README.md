# atlas-posthoc
Post-hoc diagnostics and manuscript-quality plotting for multi-chain `AtlasIO.jl` redistricting outputs.

`atlas-posthoc` is a Python toolbox for turning `AtlasIO.jl` chain outputs into reproducible convergence diagnostics, ensemble summaries, and publication-ready figures. The package is designed around the common workflow in computational redistricting research: run several independent chains, parse the saved map outputs, compute substantively meaningful observables, compare chains, and produce figures suitable for papers, talks, and internal reports.

The goal of this project is not limited to the redistricting research of any particular state, but to provide a reusable post-processing layer for future projects using `AtlasIO.jl` outputs.

## What It Is

Given multiple AtlasIO.jl output files, typically four independent chains, `atlas-posthoc` aims to produce:

- robust parsing summaries for `.jsonl` and `.jsonl.gz` AtlasIO outputs;
- canonical district assignment tables;
- ordered vote-share marginals by chain;
- ordered compactness or isoperimetric-score marginals by chain;
- max average pairwise total-variation convergence curves;
- enacted/reference-plan overlays;
- convergence-gated enacted/reference-plan comparisons;
- manuscript-ready maps and diagnostic plots;

We underscore this workflow: We first establish that the ensemble is trustworthy on the observables of interest. Then we use that ensemble to evaluate the enacted plan.

## What It Is Not

`atlas-posthoc` is not a redistricting sampler. It does not generate plans. It assumes that sampling has already been performed elsewhere, usually through `AtlasIO.jl` or related Julia redistricting tools. In fact, the first application of this package is to analyze plans generated by samplers based on `CycleWalk.jl` and `MetropolizedForestRecom`. 

It also does not attempt to be a universal redistricting analysis framework. The first goal is narrower and more practical: provide a trustworthy, reusable post-hoc pipeline for multi-chain `AtlasIO` outputs.

## Project status

This package is still under active development.

The first stable target is a diagnostic suite inspired by [this Connecticut redistricting paper](https://arxiv.org/abs/2401.17455):

- parse AtlasIO output files;
- compute ordered vote-share vectors;
- extract ordered compactness vectors;
- compute four-chain total-variation diagnostics;
- generate marginal and convergence plots;
- generate reusable convergence reports and cached manifests.

PACE and graph-partition distance workflows now live in the sibling
[`pace-for-atlas`](https://github.com/franklinxzhou/pace-for-atlas) project.

## Quick Start

### Install from GitHub

For regular users, install directly from the GitHub repository:
```
pip install "git+https://github.com/franklinxzhou/atlas-posthoc.git"
```
or, using `uv`:
```
uv pip install "git+https://github.com/franklinxzhou/atlas-posthoc.git"
```

For development, clone the repository and install it in editable mode:
```
git clone https://github.com/franklinxzhou/atlas-posthoc.git
cd atlas-posthoc
pip install -e .
```
or, with `uv`:
```
git clone https://github.com/franklinxzhou/atlas-posthoc.git
cd atlas-posthoc
uv pip install -e .
```

### Run the tests

The test suite generates small synthetic AtlasIO inputs locally. A standard Git
checkout is enough to run it.

```bash
python -m pip install -e '.[dev]'
python -m pytest
```

### Run convergence diagnostics from TOML

```bash
atlas-posthoc init analysis.toml
```

Edit the generated file with your graph, chains, and election columns. The CLI
defaults to `atlas-posthoc.toml`. The checked-in configuration uses Ohio
congressional runs 37–40 and assumes a sibling `oh-gerrymandering` checkout, as
does the configuration in `atlas-posthoc-plus`.

```bash
atlas-posthoc list
atlas-posthoc --config analysis.toml doctor convergence
atlas-posthoc --config analysis.toml run convergence --dry-run
atlas-posthoc --config analysis.toml run convergence
```

`run` defaults to `convergence`. It processes the saved maps in each chain once
and produces ordered vote-share and compactness summaries, total-variation and R-hat diagnostics,
figures, a Markdown report, and a cache manifest. Supply at least two distinct
chains, each with at least four valid maps after thinning for split R-hat.

Relative `project.root` is resolved from the TOML file's directory. All other
relative paths are resolved from the project root.

- `[chains]` supplies AtlasIO files (`.jsonl` or `.jsonl.gz`) and optional chain IDs.
- `[inputs]` supplies `graph_json`.
- `[columns]` supplies `dem_col`, `rep_col`, and optional assignment `key_cols`.
- `[analysis]` sets the district count, saved-map proposal interval, and thinning.
  Set `compute_compactness = false` for vote-share-only diagnostics.
- `[outputs]` sets the directory for results.
- `[figures]` controls paper mode.
- `[workflow.convergence]` sets TV bin widths and optional plot limits, figure
  filename prefix, and report title.

### Paper mode

Paper mode applies the manuscript figure conventions used by
`atlas-posthoc-plus`. It removes axes and figure titles, uses
Helvetica-compatible typography with STIX mathematical glyphs, embeds TrueType
text, writes vector PDF output, and labels side-by-side two- and four-panel
figures.

Set `paper_mode = true` under `[figures]` in the TOML file. For a single run,
pass `--paper-mode` or `--no-paper-mode` before the `run` command.

```bash
atlas-posthoc --config analysis.toml --paper-mode run convergence
```

For an existing Python script, enable it with the environment variable:

```bash
ATLAS_POSTHOC_PAPER_MODE=1 python3 your_analysis.py
```

Calls that request `figure.png` (or another non-PDF suffix) write `figure.pdf`
while the mode is active. Axis labels, legends, tick labels, and annotations
remain intact. With paper mode unset, all plotting APIs retain their existing
behavior and output paths.

For programmatic use:

```python
from atlas_posthoc.paper import paper_mode

with paper_mode():
    plot_vote_share_marginals(runs, output_path="figures/votes.png")
    # Writes figures/votes.pdf.
```

A self-contained example using synthetic municipal-split traces is available at
[`examples/paper_mode.py`](examples/paper_mode.py):

```bash
python3 examples/paper_mode.py
```
